# 中医辨证助手 · 开发端（插件画布）

一个**零依赖、纯本地**的可视化插件编辑器：把 `plugins/` 下的 262 个插件当成一张
「节点图」来编辑，像 Blender / n8n 那样连线改条文，不用再手写 `needs: [[...]]`。

```
双击 dev\启动开发端.bat        （或： node dev\server.js）
浏览器打开 http://127.0.0.1:3090
```

---

## 一、它编辑的到底是什么

插件就是 `plugins/<目录>/<name>.js` 一个文件，字段只有 8 个：

| 字段 | 含义 | 出现在 |
|---|---|---|
| `name` | 英文唯一标识（= 文件名） | 全部 |
| `title` | 中文名（界面、解释里用它） | 全部 |
| `kind` | `symptom` / `pulse` / `summary` / `formula` | 全部 |
| `trigger(text)` | 触发关键词：病人说的话命中任一关键词 → 判为「有」 | 症状 / 脉象 |
| `negate(text)` | 否定关键词：命中 → 判为「没有」 | 症状 / 脉象 |
| `ask` | 反问病人的原话（问诊时显示） | 症状 / 脉象 |
| `needs` | 依赖条件（**路径数组**，路径内 AND，路径间 OR） | 证候 / 方剂 |
| `contraindications` | 禁忌 / 注意事项 | 证候 / 方剂 |

图的方向：**条件节点（右侧出线）→ 依赖它的节点（左侧入线）**

```
发热(症状) ──是──┐
无汗(症状) ──是──┼──► 麻黄汤(方剂)
大烦渴(症状) ─非─┘
```

连线颜色：**是** = 青绿实线；**非** = 红色虚线（线上标「非」）。
一个节点有多条路径时，线上还会标 ①②③。

---

## 二、必须先理解的引擎语义（照实呈现，不做美化）

1. **路径内 AND**：一条路径里的条件**全部满足** → 该节点成立（yes）。
2. **路径间 OR**：多条路径里**任意一条**全部满足 → 成立。
3. **但是**：只要**任意一条**路径被某个条件**明确否定**（要求有而实际没有，或要求没有而实际有），
   整个节点就直接判为**不成立（no）**——即使另一条路径只是「还不知道」。
   这是 `engine/engine.js` 的真实行为。开发端会在模拟面板把这种情况标成
   **⚠ 路径冲突**（哪条路径满足、哪条被卡死都会列出来），但**不会替你改数据**。
4. **空路径是陷阱**：`[[]]` 这种空路径会被当成「永远成立」，所以保存时一旦发现空路径会直接**阻止保存**。

> 举例（真实数据）：麻黄汤有 3 条路径，其中路径1 = 无汗 + 恶风 + 大烦渴(非)。
> 若病人「有汗」→ 无汗被否 → 3 条路径全被卡死 → 麻黄汤判 `no`，符合「有汗就不行」的本意。
> 但若病人「太阳病=没有、发热+汗出+恶风都满足」，太阳中风会因路径1 被卡死而判 `no`，
> 即使路径2 已经满足 —— 这就是路径冲突，模拟面板会显示 ⚠。

## 三、界面速览

| 区域 | 作用 |
|---|---|
| 顶栏 | 全局统计（悬空引用 / 未被引用 / 已改动）、主服务状态、重新载入、新建节点、自动布局、保存 |
| 左栏 | 节点清单 + 搜索（中文名 / name / 触发词）+ 类型筛选 + 「未被引用 / 多路径OR / 已改动」筛选 |
| 中栏 | 节点画布：拖拽、框选、滚轮缩放、空格或中键平移、右下角小地图 |
| 右栏 | **检视器**（改所选节点的全部字段）/ **实时模拟** / **条文反向** / **问诊回放** |
| 底栏 | 选中信息、缩放与视图坐标 |

### 画布操作
- 拖空白 = 框选；按住 `Shift` 追加选择
- 拖节点 = 移动（多选一起动）；位置会存进 `plugins/.layout.json`
- 从节点**右侧圆点**拖到另一个节点上松手 = **新增依赖条件**（默认「是」；按住 `Alt` 落下 = 「非」）
- 点连线 = 选中该条件；`Delete` = 删除所选节点
- 滚轮 = 缩放；`空格`+拖 或 中键拖 = 平移；`F` = 适应全图；`Esc` = 取消选择
- 右键节点 = 快捷菜单（含「模拟中设为有/没有」「看条文树」「重命名」「查看源码」）
- `Ctrl+S` = 保存；`Ctrl+Z` / `Ctrl+Shift+Z` = 撤销 / 重做（仅限尚未保存的编辑）

### 三个面板
1. **实时模拟**：勾选症状的 是/否/未知 → 调用**真实引擎**推演，直接告诉你
   哪些方剂/证候成立、哪些被阻断（被哪个条件阻断）、禁忌汇总、⚠ 路径冲突、引擎下一步会问什么。
   画布上同步着色（绿=成立、红=不成立、灰=未知）。
2. **条文反向**：以任一节点为根，展开完整依赖树（每条路径、每个是/非条件、递归到症状），
   叶子节点会显示 `ask` 原话——就是「医生该怎么问」。底部列出谁依赖它。
3. **问诊回放**：设定病人的真实症状，让引擎按**真实 Asker 逻辑**一步步问下去，
   看候选方剂怎么收敛到唯一（或为什么收敛不了）。

## 四、保存是怎么写回磁盘的（这是本工具最讲究的部分）

点「保存」后是**两阶段**：

1. **预览**：服务端算出每个文件的新内容，逐行 diff 显示，并列出风险提示。此时**什么都没写**。
2. **确认写回**：备份 → 写盘 → 立刻用 `core/loader.js` 复核。

保证措施：

- **只动真正变化的字段**。插件文件里作者手写的条文注释（例如
  `// 第26条: 服桂枝汤大汗出后大烦渴不解脉洪大者…`）会被完整保留——
  自测保证：对全部 262 个现有插件「解析 → 原值回灌」**字节级一致**（`node dev/selftest.js`）。
- **改名 / 删除节点引起的引用变化**，只替换 `needs` 数组里的字符串字面量，
  数组内的路径注释、缩进、逗号风格都不动。
- **写盘前先在临时目录做一次编译验证**：把全部最终源码写进临时目录并真跑一遍 loader，
  语法错误、重名、悬空引用、空路径一律**阻止保存**。
- **原文件先备份**：`dev/.backups/<时间戳>/<原相对路径>`。
- **冲突检测**：如果文件在磁盘上被外部改过（手工编辑过），保存会被拒绝，要求先「重新载入」。
- **只允许写 `plugins/` 下的 `.js`**，路径完全由 `name` / `kind` 推导，不接受任意路径。
- 改 `kind`（例如症状→方剂）会**连带把文件移动到对应目录**，不是只改一个字段。

## 五、保存后如何生效（主服务热重载）

`server.js` 已经启用 `core/loader.js` 的 `watchPlugins`：任何 `plugins/*.js` 的改动都会在
300ms 内自动重载（开发端保存后还会额外调 `POST /api/dev/reload` 立即重载，保证「刚保存就能用」）。

- 新会话立刻用上新插件；**已经在进行的会话**仍然用旧插件（引擎不会中途改判）。
- 顶栏右侧显示主服务是否在跑、已载入多少插件。
- 也可以手改文件——同样会自动重载，不必重启进程。

## 六、目录与端口

| 项 | 位置 / 值 |
|---|---|
| 开发端服务 | `dev/server.js`，只监听 `127.0.0.1:3090`（`DEV_PORT` 可改） |
| 页面 | `dev/public/` （`index.html` / `style.css` / `js/*`，纯原生 ES module，无 CDN） |
| 布局文件 | `plugins/.layout.json`（只存坐标，不污染插件数据） |
| 备份 | `dev/.backups/<时间戳>/` |
| 主服务 | `127.0.0.1:3088`（`PORT` 可改；开发端用 `MAIN_PORT` 指向它） |
| 打包 | **`dev/` 永远不会进入 `dist`**（`打包.ps1` 只复制明确的文件清单，并额外清理 `.layout.json`） |

## 七、自测与回归

```powershell
node dev\selftest.js
```

覆盖：插件解析、**无损回灌（必须 262/262 字节一致）**、定点改写、多路径 OR 往返、
新文件生成可被 loader 接受、改名时的全局引用改写、结构问题统计（悬空引用 / 孤立症状 / 自相矛盾）。

当前状态：**571 项断言全部通过**。

另外原有的 7 个引擎测试（`test-mvp.js`、`test-yangming.js`、`test-jueyin.js`、`test-taiyin-shaoyin.js`、
`test-undo.js`、`test-asker.js`、`test-hotreload.js`）仍可用 `node test-xxx.js` 单独跑，
用来确认你的条文改动没有破坏既有判定。

前端静态体检（不需要浏览器）：

```powershell
node dev\checkui.js
```

检查 import/export 是否对得上、`getElementById` 用到的 id 是否都在 `index.html` 里、
引用的静态资源是否存在——能在打开页面前就抓出大部分低级错误。
