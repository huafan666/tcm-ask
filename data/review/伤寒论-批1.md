### 原文踩到的四个坑（都写进工具注释了）

1. 「零」有四种写法：ASCII `0`、全角 `０`、汉字 `〇`、全角字母 `Ｏ`（第 130 条用的就是字母 O）
2. 条末分隔符有时是 `、` 有时是 `，`（第 114 / 128 条用的逗号）
3. 有 7 条编号顶格（前面没有全角缩进），如第 194 / 214 / 215 / 245 / 261 / 351 / 352 条
4. Gutenberg 转义把两处编号打坏了：第 110 条成 `&#0;一 0 `、第 311 条成 `三&#0;一`，按宋本还原

所以抽取不用「匹配所有行首编号」这种笨办法，改成**按顺序找下一条**：
已知当前条号 n，就找第一个「编号解出来正好等于 n+1」的行。

## 二、新增逐条审核工作台

`tools/audit-shanghanlun.js`

把「条文」和「知识库现状」摆在一起：

```
【伤寒5.25】取桂枝汤，大汗出，脉洪大者……若形似疟，一日再发者，汗出必解，宜桂枝二麻黄一汤。
   方：桂枝二麻黄一汤 (guizhi_er_mahuang_yi_tang)
      needs=["fever.yes","cold_aversion.yes","periodic_chill_fever.yes","sweat.yes"]
   条文否定词：…
   症状命中：汗出
```

用法：`--ch 5` 看某一篇 / `--seq 31-60` 看某一段 / `--missing` 列缺失方名汇总。

方名匹配做了三层容错：繁简转换 → 别名（括号里的）→ 编辑距离 ≤1（吃掉原文错字
「桂校附子汤」「自虎汤」）→ 前后缀包含（原文常把「桂枝去芍药加蜀漆牡蛎龙骨救逆汤」
缩写成一截）。

**关于「条文否定词」这一栏**：一开始我让它自动判断「这个『不呕』有没有落进 needs」，
结果它把「不呕」对到了「吐血」（呕血的 trigger 也含「呕」）、把「不解」对到「便秘」
（便秘的 trigger 含「解不出大便」）。**这种自动判断比没有更糟**，所以改成只把原文的
否定短语列出来，判断留给人。
