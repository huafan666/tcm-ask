# 糖尿病（消渴）实测：模拟问诊与结果评估

用户要求：「试一个糖尿病的看看什么结果，你模拟一下可能的回答」。

下面用一个典型 2 型糖尿病病人跑完整问诊流程。病人按「知道自己有哪些症状」作答
（该有的答是、没有的答否），这是**最有利于系统**的口径——所以结论偏乐观，
真实病人答一堆「不知道」只会更差。

---

## 一、病人设定与主诉

**主诉**：特别口渴，一天要喝好几壶水，喝完还是渴，嘴里舌头干得厉害，饭量很大但人越来越瘦，
一动就出汗，浑身没劲。

| 症状 | 中医意义 |
|---|---|
| 大渴、喝水不解 | 津液不足 / 里热 |
| **口干舌燥** | 津气两伤（金匮 13.12 白虎加人参汤的抓手） |
| 多食 | 中消（消谷引食） |
| 消瘦 | 消烁肌肉 |
| 乏力 | 气虚 |
| 动则汗出 | 表虚 / 阳不固 |

---

## 二、实测结果（改之前 / 改之后）

### 改之前

```
问诊 33 轮
成立的方剂：白虎加人参汤、白虎汤、文蛤散、补肾组合
```

两个问题：
1. **白虎汤 和 白虎加人参汤 同时成立**，而且是靠**同一条路径**成立的
   （`大烦渴 + 不恶寒`）——库里根本没有能区分它们的症状。
2. 「口干舌燥」这个金匮 13.12 明写的抓手，库里没有对应节点，
   只能用「嗓子发干」（throat_dry）凑，而咽干 ≠ 口腔津亏。

### 改之后

```
问诊 36 轮
成立的方剂：白虎加人参汤、文蛤散、补肾组合
```

白虎汤被正确排除了——因为病人**口干舌燥 = 是**，那是加人参的指征。

### 换成下消型（多尿为主）

**主诉**：尿特别多，一晚上起夜三四次，总是口渴，腰酸没劲，人也瘦了。

```
问诊 26 轮
成立的证候：消渴、肾精血虚
成立的方剂：八味肾气丸、补肾组合、补肾精血
```

**八味肾气丸**——对上了金匮 13.3「男子消渴，小便反多，以饮一斗，小便一斗，肾气丸主之」。

### 换成纯白虎汤证（大渴不怕冷、不口干）

```
问诊 25 轮
成立的方剂：白虎汤、文蛤散
```

白虎加人参汤被排除。三条互斥的用例现在分得开了。

---

## 三、这次发现并修掉的问题

### 1. 新增症状节点：`mouth_dry`（口干舌燥）

「渴」和「燥」在中医里是两件事：

- **渴** = 想喝水（津液不足的整体感觉）→ `thirsty`
- **燥** = 口腔、舌头本身没津液（局部干燥）→ 原来只有 `throat_dry`（嗓子发干）

金匮 13.12「渴欲饮水，**口干舌燥**者，白虎加人参汤主之」——抓手就在「口干舌燥」，
它标志的是**津气两伤**。咽干是咽部的事，不能顶替。

新节点：
```
问：是不是嘴里、舌头上干得厉害，像没有口水一样？
词表：口干舌燥 / 口舌干燥 / 舌上干燥 / 舌头干 / 嘴里干 / 嘴巴干 / 口燥 …
```
挂在「口咽部不适」分组，走「呼吸咽喉」这一问。

### 2. `severe_thirst`（大烦渴）的问句一句话问了两件事

原问句：「是不是特别口渴、**心里烦躁**，喝很多水也不解渴？」

「渴」和「烦躁」各有专门节点（`restless`）。病人「特别渴但不烦躁」时会答「否」——
糖尿病的多饮正是这种情况，白虎汤、白虎加人参汤、文蛤散会一起丢掉。

改成：「是不是渴得很厉害，喝很多水也不解渴？」

### 3. 白虎汤 / 白虎加人参汤 按原文重新分开

原文里加人参的指征**不是「渴得更厉害」，而是「津气两伤」**：

| 条文 | 指征 |
|---|---|
| 26 条「服桂枝汤，大汗出后，大烦渴不解」 | 汗多伤津 |
| 169 条「大渴，舌上干燥而烦」「时时恶风」 | 口干舌燥 / 恶风 |
| 170 条「背微恶寒」 | 背恶寒 |
| 金匮 13.12「渴欲饮水，口干舌燥者」 | 口干舌燥 |

改动：

```
白虎汤        severe_thirst + cold_aversion.no + mouth_dry.no   ← 加了「不口干」
白虎加人参汤   severe_thirst + cold_aversion.no + (mouth_dry 或 wind_aversion 或 back_cold_patch)
              + 金匮 13.12 原文路径 thirsty + mouth_dry
```

两边一配，口干与不口干就分得开了。若病人答「不知道」，路径不阻断，两个方都留在候选里——
这是对的，本来就该靠脉和舌去定。

### 4. 系统闸门被跳过之后，整个系统就再也不问了

实跑发现的：病人只说了一句「口渴」，**饮食系统的闸门就被跳过了**
（因为组已经被这个子症状点亮，闸门不再问），于是饮食系统一个细化问题都没问——
「多食易饥」（中消的核心症状）永远问不出来。

修法：闸门没问过、但系统已经被点亮的，也给一个较小的追问额度（2 个），
并且只问「还有候选方真的需要」的症状。

### 5. 基准测试的人工病人自相矛盾（测法问题）

修完上面几条后，基准里白虎加人参汤反而「丢了」。查下去是**测法造出来的假象**：
`bench-synthetic` 只用一条 needs 路径生成病人，白虎加人参汤那条路径写的是
「大烦渴 + 不恶寒 + 口干舌燥」，于是这个病人被问到「口渴」时答**否**——
可「大烦渴」本身就蕴含「口渴」，病人是自相矛盾的。

修法：生成人工病人后，先用引擎的关系约束补全一遍，再拿来作答。

## 四、还不对 / 还缺的地方（诚实结论）

### 1. 多食（中消）问不出来——这是知识缺口，不是策略问题

`polyphagia`（吃得多还容易饿）在库里**没有任何方剂依赖它**。
问诊器只问「还有候选方需要的症状」，没人需要它，所以永远不问。

为什么没有方？金匮 13.2「趺阳脉数，胃中有热，即消谷引食，大便必坚，小便即数」
**这一条本来就没给方**（后半段直接转去讲淋病了）。中消的方是后世补的（玉女煎一类），
金匮里没有对应条文。

要修就得补条文/方剂，不能靠改问诊策略。

### 2. 「补肾组合」每一案都成立

它是自造方，needs 是 `体力很差` 单条。按用户此前的决定保留不动，
所以只要病人说「没劲」，它就成立，会一直占着结果页。

### 3. 糖尿病并发症没有对应节点

视物模糊、伤口不易愈合、皮肤瘙痒（有 skin 族但没专门节点）、
尿有甜味/尿浊——库里都没有。手足麻木有（`limb_numbness`），
它点亮「血痹」→ 黄芪桂枝五物汤，这条反而对得很准（糖尿病周围神经病变，中医按血痹治）。

### 4. 脉象完全不参与

`dependsOnPulse` 直接把靠脉判的方剂排除掉。消渴的「趺阳脉浮而数」「脉洪大」
这些最硬的鉴别信息目前用不上。

这个交换是划算的。
