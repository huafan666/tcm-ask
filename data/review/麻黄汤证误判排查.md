# 麻黄汤证被判成乌头汤/桂枝附子汤——原因排查与修复

**用户反馈**：输入麻黄汤的临床症状后，最后输出 8 个候选方：

```
补肾组合（泽泻+补骨脂，阳起石+细辛，乌药，炮附子）、柴胡桂枝汤、大青龙汤、
桂枝附子汤、乌头汤、小柴胡汤、小青龙汤、一物瓜蒂汤
```
辨证结论落在「乌头汤 + 桂枝附子汤（寒湿痹阻、表阳不足）」——
麻黄汤证被当成了历节/寒湿痹。用户问：**原因在哪里？**

下面每条原因都有实跑证据。

---

## 一、把 8 个候选方逐个对回条件（这是理解问题的起点）

| 候选方 | 命中它的那条路径 | 原文问题 |
|---|---|---|
| 乌头汤 | 骨节疼烦不可屈伸 + 关节痛得剧烈 | 两条都是笼统节点，关节僵+痛剧就成立 |
| 桂枝附子汤 | 身体疼烦不能转侧 + 不渴 | 「不渴」是阴性条件，一问就成立 |
| 大青龙汤 | 溢饮 = 体痛 + 身重 | 身痛+身重就是溢饮？ |
| 小青龙汤 | 溢饮 = 体痛 + 身重 | 同上 |
| 一物瓜蒂汤 | 发热 + 体痛 + 身重 | 这跟麻黄汤证几乎完全重合 |
| 柴胡桂枝汤 | **食欲差 + 体痛** | 自造的松路径，原文没有 |
| 小柴胡汤 | **食欲差**（单条） | 「但见一证便是」保留 |
| 补肾组合（自造） | **体力很差**（单条） | 保留 |

也就是说：病人只要「身疼 + 身重 + 体力差 + 没胃口」，这 8 个就全冒出来，
而真正该出的**麻黄汤一个都没进来**。

---

## 二、直接原因：出汗闸门答「否」，把「无汗」也判成了「否」

这是最要命的一条，而且是逻辑反了。

问诊里有一个系统闸门：「**是不是身上会出汗？**」
病人（麻黄汤证）答「**否**」——意思是「我不出汗」。

引擎里，症状筛选组答「否」⇒ 组下所有子症状一次性判否（析取否定，本意是对的）。
但出汗这一族的子症状里**同时挂着 `sweat`（有汗）和 `no_sweat`（无汗）**，
于是「我不出汗」被记成了：

```
sweat = 否        ← 对
no_sweat = 否     ← 错！不出汗就是无汗，应该是「是」
```

实测：

```
答否前 no_sweat=yes
答否后 no_sweat=no   →  麻黄汤=no   大青龙也有同样的隐患
```

而靠「无汗」判的方剂有 **14 个**：麻黄汤、大青龙汤、葛根汤、小青龙汤、
甘草麻黄汤、麻黄加术汤、麻黄附子汤、麻黄醇酒汤、麻黄连翘赤小豆汤、
桂枝去桂加茯苓白术汤、五苓散、刚痉、溢饮……

**一个错误答案，整片麻黄类方剂集体出局。**

### 修法：新增「互补」关系（COMPLEMENT）

上一轮建的 `MUTEX`（互斥）只管「不能同时是」，管不了「不能都不是」。这里需要的是**正好相反**：

```
COMPLEMENT：有汗 ↔ 无汗
   有汗=是 ⇒ 无汗=否
   有汗=否 ⇒ 无汗=是      ← 这次补上的
   无汗=是 ⇒ 有汗=否
   无汗=否 ⇒ 有汗=是
```

为什么便秘/下利不能这么做？因为大便还有「正常」这一种，
`便秘=否` 推不出 `下利=是`。**出汗是二分的**，所以才能互补。

顺带补了词表：`no_sweat` 原来只认「无汗/没汗/没有汗」，不认「**不出汗**」，
于是病人说「不出汗」时只有 `sweat` 被否，`no_sweat` 一直是 unknown。

## 三、连带暴露的引擎 bug：判成「否」就再也回不来了

修完上面那条还是不行，实测仍然是 `麻黄汤=no`。追下去发现是 `evalOne()` 的问题：

```
setDirect('sys_sweat','no')
  → 先把 sweat / no_sweat 逐个置否（立刻触发依赖重算）
     此时 no_sweat=否 → 麻黄汤三条路径全断 → 麻黄汤=否
  → 关系约束再把 no_sweat 翻回「是」
     麻黄汤重新求值：路径没被阻断，应该回到 unknown
     但旧代码只有 yes / no 两个出口，没有「回到 unknown」这条路 ← 卡死
```

`evalOne` 是单调的：`no` 是永久判决。任何**瞬时的中间状态**都能把方剂永久判死。

修法：`evalOne` 改成真正的三态，允许 `no → unknown` 回退：

```js
const next = anyPathOk ? 'yes' : (allPathsBlocked ? 'no' : 'unknown')
if (this.state[name] !== next) this.state[name] = next
```

## 四、根本原因一：疼痛族的粒度太粗（用户点名的「骨头痛要细分」）

现状是几个「万金油节点」把七八种不同的疼全揉在一起：

| 节点 | 被多少个方/证引用 |
|---|---|
| `body_pain` 体痛 | **13 个**（麻黄汤证、溢饮、太阳伤寒、金疮、肾著、附子汤、新加汤、麻杏薏甘、薯蓣丸、一物瓜蒂汤……） |
| `joint_pain_rigid` 骨节疼烦不可屈伸 | **8 个**（历节、湿痹、风水、温疟、附子汤、甘草附子汤、桂枝附子汤、桂枝芍药知母汤、乌头汤） |
| `body_ache_stiff` 身体疼烦不能转侧 | 3 个 |

而对得上的原文其实是**完全不同的疼**：

- 35 条「头痛发热，**身疼腰痛，骨节疼痛**，恶风，无汗而喘」——麻黄汤
- 174/175 条「**身体疼烦，不能自转侧**，不呕不渴」——桂枝附子汤
- 5.13「病历节**不可屈伸**，疼痛」——乌头汤
- 「诸肢节疼痛，**身体尪羸，脚肿如脱**」——桂枝芍药知母汤
- 「骨节疼烦，**掣痛不得屈伸，近之则痛剧**」——甘草附子汤
- 「太阳中暍，**身热疼重**」——一物瓜蒂汤

问诊上这些是**能问出来的**（疼在皮肉还是骨节、能不能翻身、按着更疼还是不动也疼、
有没有红肿发热、怕冷还是怕热），但库里只有一个「是不是身上痛」。

### 修法：新增三个能问出来、且真能分方证的节点

| 新节点 | 问句 | 用来分谁 |
|---|---|---|
| `lower_back_pain` 腰痛 | 是不是腰这里疼？（不是酸软，是痛） | 麻黄汤（35 条「身疼腰痛」）vs 腰酸（肾虚一路） |
| `joint_red_hot` 关节红肿发热 | 是不是关节那块又红又肿、摸着还发烫？ | **热痹**：桂枝芍药知母汤 |
| `joint_cold_aggravated` 关节怕冷 | 是不是一着凉、一变天就更疼，热敷着反而舒服些？ | **寒痹**：乌头汤、甘草附子汤 |

后两个互为**互斥**（寒痹 / 热痹只能是一个），这条寒热鉴别原来是完全缺的。

### 顺带修掉两个互相误吃的词表

- `yaosuan`（腰酸）的 trigger 里有「**腰痛**」，而它的问句写着「是酸不是胀痛、刺痛」。
  于是「腰痛」既点亮腰酸、又顺着「腰酸 → 肾精血虚 → 补肾精血」一路误判。
  现在「腰痛」只归 `lower_back_pain`。
- `guoming_hongzhong`（过敏红肿）的 trigger 里有「**肿痛**」「**肿了**」，
  病人说「关节肿痛」会被当成皮肤过敏。改成只管皮肤上的红肿。

## 五、根本原因二：方剂路径太松，缺阴性鉴别

| 方剂 | 原路径 | 问题 | 处理 |
|---|---|---|---|
| 柴胡桂枝汤 | `low_appetite + body_pain` | 食欲差 + 身痛就成立，麻黄汤证必然中招。146 条原文要的是「**支节烦疼**」 | 删掉这条；改成 `发热+微恶寒+关节疼` / `往来寒热+关节疼` / `往来寒热+身痛` |
| 乌头汤 | `关节僵 + 关节痛剧烈` | 和热痹分不开 | 加 `joint_red_hot.no`（寒湿历节，不红不热）；再补一条 `关节僵 + 关节怕冷 + 不红不热` |
| 一物瓜蒂汤 | `发热 + 体痛 + 身重` | 与麻黄汤证几乎重合 | **暂未改**（原文就是「身热疼重」，没有更多可判的字面条件），留待补「夏月伤冷水」这类语境节点 |
| 小柴胡汤 | `食欲差` 单条 | 「但见一证便是，不必悉具」（101 条） | 按用户此前决定保留 |

## 六、根本原因三：问诊器对「方 → 证候 → 症状」只问了第一层

这条是修完上面所有问题后**还剩 8 个候选**才暴露出来的。

`requiredLeaves()` 收集「这个方要问哪些症状」时，遇到 needs 里挂的是**证候**
（百合病、梅核气、虚劳、温疟、血痹……）就直接跳过——因为证候自己没有 trigger、问不出来。

后果：**证候永远定不下来 → 靠证候判的方永远赖在候选里，一辈子问不到。**

实测那 8 个候选里，6 个都是这种「单挂一个证候」的方：
白虎加桂枝汤(温疟)、白芍当归身白术(肝血不足)、半夏厚朴汤(梅核气)、
黄芪桂枝五物汤(血痹)、熟地黄…(肝肾不足/肾血不足)、蜀漆散(牝疟)。

修法：`requiredLeaves` 递归往下钻，把证候底下的症状也当作可问的（深度上限 4，防环）。

---

## 七、根本原因四：结果展示把「候选」藏起来了

- `stateText()` 只把 yes / no 的节点给大模型，**unknown 的候选方一个字都不写**，
  大模型很容易理解成「没提到的就是没有」。
  → 现在补一段「仍未被排除的候选方（N 个，条件尚未问齐）」。
- 候选只剩 1 个、但条件还没问齐、方剂状态是 unknown 时，
  结果页会显示「未收敛到具体方剂」——其实答案已经唯一了。
  → 现在这种情况下把它作为唯一候选交付（带 `soleCandidate` 标记）。

## 八、修完的实测

### 麻黄汤证（伤寒 35 条：头痛发热、身疼腰痛、骨节疼痛、恶风、无汗而喘）

| | 修之前 | 修之后 |
|---|---|---|
| 候选方 | 8 个（麻黄汤不在里面） | **1 个：麻黄汤** |
| 成立的方剂 | 乌头汤、桂枝附子汤（错） | **麻黄汤** |

### 寒热痹分得开了

| 病人 | 结果 |
|---|---|
| 关节痛剧、弯不下去、一变天就更痛、热敷舒服（寒痹） | 乌头汤 |
| 关节又红又肿又烫、痛得伸不直（热痹） | 桂枝芍药知母汤 |
| 浑身烦疼、不出汗（湿病） | 麻黄加术汤 + 桂枝附子汤 |

### 基准（口径不变）

| 指标 | 上一轮 | 本轮 |
|---|---|---|
| 教科书病人：目标方保留率 | 100% | **100%** |
| 教科书病人：平均剩余候选方 | 18.8 | **18.5** |
| 教科书病人：问完仍未唯一 | 12/30 | **6/30** |
| 教科书病人：平均问题数 | 27.1 | 27.9 |
| 真实医案（51 例）：目标方保留率 | 100% | **100%** |
| 真实医案：平均剩余候选方 | 242.0 | 242.0 |

「问完仍未唯一」从 12/30 降到 6/30——递归展开证候之后，
原来「问不下去了」的那批病例现在能继续往下问。

## 九、还没解决的（写下来免得忘）

1. **一物瓜蒂汤**仍是 `发热 + 体痛 + 身重` 就成立。原文是「太阳中暍，身热疼重，
   此以**夏月伤冷水**，水行皮中所致也」——要真正区分，需要补一个「夏月 / 贪凉饮冷」
   的语境节点，这次没做。
2. **小柴胡汤**（食欲差单条）、**补肾组合**（体力差单条）按用户此前的决定保留，
   它们会一直待在候选里，这是有意为之。
3. 脉象一律不参与（`dependsOnPulse` 直接把靠脉判的方排除），
   所以「脉浮紧」这类条文里最硬的鉴别信息目前完全用不上。
