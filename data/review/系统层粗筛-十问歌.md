# 系统层粗筛（十问歌） + 引擎 OR 语义修正 + 提示移入聊天

**用户要求**：
1. 红色大类筛选提示太突兀，放进聊天框里一起，不要弹出来
2. **（重点）** 粗筛逻辑还不够，尽早就该定位到关键的地方；例如大便问题一次性就问清楚，
   排除掉的就不要再问了；必须统筹所有症状，按人的习惯方式粗筛——
   「高手中医就可以达到这种程度，我的目的就是这样」

---

## 一、发现并修掉引擎一个真 bug（这次最大收获）

排查基准测试「目标方丢失」时发现：**`anyPathBlocked` 语义错了**。

`needs` 的多条路径之间是 **OR**（任一路径成立即成立），但旧代码是：

```js
// 旧（错）
if (anyPathOk) → yes
else if (anyPathBlocked) → no      // ← 只否掉一条路径就判 no
```

按集合论，¬(A∨B) 才等价于 ¬A∧¬B；**只否定其中一条路径，推不出整个节点不成立**。

**实例**（百合地黄汤）：
- 百合病有 3 条路径。病人符合第 1 条（想睡睡不着那种），但其中两个症状还没问到
- 问诊问到第 2 条路径的症状（想躺躺不住/想走走不动）→ 答「没有」
- 旧逻辑：有一条路径被阻断 → **百合病 = no** → 百合地黄汤整块丢失

**修法**：

```js
// 新（对）
if (anyPathOk) → yes
else if (allPathsBlocked) → no     // 必须**所有**路径都被明确阻断
// 否则保持 unknown
```

这条修正让基准测试的目标方保留率从 76.7% 回到 **100%**。

> 注：这个 bug 之前没暴露，是因为旧问诊是「按区分度随机跳」，很少把某条路径完全问死。
> 现在系统层会成体系地排除整个系统，才把它逼出来。

覆盖 244 / 256 个症状（95.3%）。只有 2 个症状跨系统（阴部发冷、腰冷）。

### 问诊流程（这才是「按人的习惯」）

```
① 按十问歌顺序，逐个系统问一句复合问题
   例：「大便怎么样——干硬难解、稀溏不成形、一天几次、带血或发黑，还是正常？」
   ├ 答「没有」→ 这个系统**所有症状一次性判否**，后面永不再问 ✓（用户要的）
   ├ 答「有（但没细说）」→ 进这个系统，追问几个最关键的子症状（最多 5 个）
   └ 病人直接描述（「大便稀，一天两次」）→ 直接解析，不再追问这个系统 ✓
② 系统过完 → 剩下的才按区分度问具体症状
```

**已经提到的系统优先问**：病人先说「咳嗽」，呼吸系统排到最前，但不能跳过寒热/汗这些基础项
（所以实际是先问几个基础系统，再进呼吸）。

### 跳过无关系统

某个系统里的症状如果跟当前剩余候选方**完全无关**，直接跳过不问。
实测妇科在很多病例里就是被这样跳过的。

## 三、实测效果

### 教科书病人基准（30 个方剂，每问 2 秒）

| 指标 | 改之前（只有维度分组） | 改之后（系统层） |
|---|---|---|
| 平均问题数 | 30 问 | **29.1 问** |
| 平均耗时 | 60 秒 | **58 秒** |
| **目标方保留率** | 96.7% | **100%** |
| **平均剩余候选方** | **66.2 个** | **30.2 个** |
| 其中粗筛问题 | 4.0 问 | **11.4 问** |

**同样的 30 问、同样的 60 秒，把剩余候选方砍掉一半以上，而且召回做到 100%。**

### 关掉最后 4 个漏网方剂（用户提议的验证）

用户提议：**那些单症状的方剂应该也能被前面的粗筛排除掉，把可以归类的连接起来。**

验证方式：把所有 12 个系统**全部答「没有」**，看还剩几个方剂。

| 阶段 | 全系统答「没有」后仍存活的方剂 |
|---|---|
| 修补前 | **4 个**：桂枝加桂汤（气上冲）、黄芪党参升麻（下坠）、十枣汤（悬饮）、乌梅丸（虫积） |
| 修补后 | **0 个** ✓ |

这 4 个的条件恰好都不在任何系统里。修法两类：

**A. 按语义归进现有维度分组**（6 处）
| 分组 | 补入 | 理由 |
|---|---|---|
| `cough_any` | 咳嗽时胁下牵扯痛、吐腥臭浊痰、**咯血**、喉咙水鸡声 | 都是咳嗽/呼吸的具体表现 |
| `hypochondrium_any` | 胆结石点压痛 | 在右胁 |
| `limb_any` | 脚气腿脚疼痛 | 属肢体 |
| `abdomen_any` | 虫积、胃痛 | 在腹部 |
| `edema_any` | 卧蚕明显 | 眼泡浮肿 |
| `gyneco_any` | 出血色黑 | 多用于妇科漏下 |
| `mouth_throat_any` | 流鼻血 | 口咽鼻这一问 |

**B. 用系统的 `extra` 字段显式挂上**（语义上被刻意排除在维度分组之外的）
| 系统 | extra | 为什么不进维度分组 |
|---|---|---|
| 胸腹 | 恶心、气上冲、下坠 | 恶心不是呕吐动作（刻意不进呕吐族） |
| 出汗 | **无汗** | 与「出汗」相反，刻意不进 sweat_any；但出汗这一问必须能把它判否 |
| 寒热 | 似冷非冷似热非热 | 属寒热范畴，但不是具体寒/热症状 |
| 饮食 | 口干只想漱口、喜冷饮 | 前者是瘀血特异表现、后者是饮食偏好 |
| 头身 | 耳鸣 | 属头面但不成组 |

**症状覆盖率：92.6% → 100%（256/256，未归族 0 个）。**

### 指标命名修正（之前报错了一个数）

原来基准里 `converged` 其实是「**没有可问的问题了**」，不是「收敛到唯一」，我之前把它当后者报了，现在拆成两个：

| 指标 | 30 问 / 56 秒 | 44 问 / 89 秒 |
|---|---|---|
| 目标方保留率 | **100%** | **100%** |
| 平均剩余候选方 | **26.7 个** | **5.8 个** |
| 收敛到唯一候选 | 0% | 0% |

**诚实结论**：这套系统目前不可能收敛到唯一答案，但**永远不会漏掉正确的那个**，
把 250 个候选压到 6~27 个。从临床现实看，这就是「鉴别诊断候选清单」该有的样子。

## 四、顺手补的缺口：头痛节点

排查系统划分时发现**库里根本没有「头痛」节点**——而头痛是极常见的症状：
金匮 17.11「干呕吐涎沫，**头痛**者，茱萸汤主之」、伤寒太阳病头项强痛、少阳头痛、厥阴巅顶痛都用得到。

已补 `headache` 头痛节点。

## 五、顺手修的两个「真源不同步」问题

`data/symptom-groups.js` 是分组真源，`plugins/symptoms/*_any.js` 是生成物。
之前几轮修改**只改了生成物没改真源**，一重新生成就被覆盖：

| 项 | 问题 | 处理 |
|---|---|---|
| `vomit_any` | 收紧掉的「想吐/吐出来」被重新生成覆盖回去了 | 写回真源 |
| `bleeding_any` | 手工加的 `hemoptysis` 丢了 | 写回真源 |
| `sleep_any` | 上一轮加的 3 个睡眠节点丢了 | 写回真源 |

并新增 `tools/check-group-drift.js`——专门检查「生成物 vs 真源」漂移，防止再犯。
现在漂移 **0 项**。

### 关于 test-negate 里那条断言的修正

原来有一条 `桂枝汤被排除（无汗）→ 期望 no`。修了 or 语义之后，正确结果是 **unknown**
（桂枝汤还有「妊娠+呕吐+食少」「产后」两条路径没被问到，推不出不成立）。
断言已改为 `!== 'yes'`，并新增一条：把妊娠/产后也答「没有」之后，桂枝汤才变 `no`——
这才是 or 语义下「排除」的正确条件。
