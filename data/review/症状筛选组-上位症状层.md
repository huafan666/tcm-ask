# 症状筛选组（上位症状层）· 设计与审核台账

**需求来源**：用户 2026-02 提出 —— 症状要先做一次粗筛，例如「呕」下面有吐血、吐水、吐涎沫、吐脓血等多种类型，
它们都属于「呕」，所以先用「呕」快速缩小范围，再问具体的。
**关键约束**：区分维度不是「轻重」，而是**属性**（吐不吐东西、吐出来的是什么）。

---

## 一、设计规矩（用户确认）

| 编号 | 规矩 |
|---|---|
| 1 | 上位节点**只做筛选提示**，和后面的架构区分开，**不进 needs 推理** |
| 2 | 有歧义的一律不归族，各自单列，让病人答准确 |
| 3 | 咯血（咳出来的血）**单独分开**，绝不是吐血 |
| 4 | 恶心（想吐没吐）**不算**呕吐；干呕（有动作没东西）**算**呕吐 |
| 5 | 命名用 `xxx_any`，中文标题带限定语防误解 |
| 6 | 允许多父：一个症状可同时属于多个维度（便脓血 → 下利族 + 出血族） |
| 7 | 新建 `kind: 'symptom_group'`，画布单独配色、标「症状筛选」 |

## 二、引擎改动（约 30 行，engine/engine.js）

### 为什么必须改引擎

如果上位节点用 `needs` 去 OR 子节点：

```js
needs: [['hematemesis.yes'], ['vomit_saliva.yes'], ...]
```

会被 **anyPathBlocked** 打死：病人说「不吐血」→ `hematemesis` = no → 第一条路径被阻断 →
**整个「呕」判成 no**，可他明明在吐涎沫。

这个坑本轮踩过两次（肠痈、桂枝茯苓丸），是既定规矩「多路径间禁止同节点 yes/no 互斥」的同一根因。

**实测证据**（改之前）：

| 输入 | 结果 |
|---|---|
| `没有出冷汗` | 出冷汗 = no（正确） |
| 若「汗」是纯词表并集 | 「汗」会被判 **no** ← 错误，他明明在出汗 |

### 改成了什么

新增 **rollup（汇入）** 语义：

1. 任一子症状 = `yes` ⇒ 组 = `yes`
2. 子症状 = `no` **不影响**组（只否定了一个子类，不等于否定整个大类）
3. 组**永不被判 no**，只有 `yes / unknown` 两态
4. 组自己的 trigger 仍可用于「病人只说了大类」的粗筛，且不会被否定词带成 no

代码位置：
- `feed()`：组跳过 `negateHit` 与 `polarityOf === 'negated'` 的置 no 分支
- `propagate()`：每轮在 needs 求值后加一段「组汇入」，和 needs 一起迭代到收敛

## 四、为解决「病人误解」而专门做的 5 件事

### ① 顺手发现并修掉的数据 bug

`core/loader.js` 有 `mod.kind = mod.kind || 'symptom'`，
所以 `plugins/formulas/` 里漏写 `kind` 的文件会被**当成症状注册**。实测发现 6 个：

`baihe_dihuang_tang`、`baihe_huashi_san`、`baihe_jizi_tang`、`baihe_xifang`、`baihe_zhimui_tang`、`huashi_daizhe_tang`（百合病六个方）

已全部补上 `kind: 'formula'`。另删掉垃圾节点 `niu`「牛」。
症状数 263 → 256（-6 方剂 -1 垃圾），方剂 244 → 250。

### ② 恶心与呕吐彻底分开

原 `vomiting`（呕逆）的 trigger 里有「想吐」「欲吐」，
所以「恶心想吐但没吐」也会点亮「呕吐」——正是用户指出的误解。

- 新建 `nausea` 恶心（想吐但没吐）
- `vomiting` 去掉「想吐/欲吐」，问法改成「是不是**真的有过呕吐动作**」
- `vomit_on_food` 的「吃就想吐」等口语说法移交 `nausea`，只保留条文的「食谷欲呕」类

### ③ 咯血单独立节点

库里原来**根本没有咯血节点**，说「咳出血来」什么都点不亮——这是个漏。
新建 `hemoptysis` 咯血（咳出来的血），归入**出血族**，**绝不进呕吐族**。

### ④ 组的词表禁止出现内容物词

体检工具内置黑名单：`吐血 / 咯血 / 咳血 / 吐涎沫 / 吐蛔 / 吐脓 / 吐痰 / 便血 / 尿血 / 崩漏 / 黑便 / 想吐 / 欲吐 / 吐出来`。

这个黑名单**抓到了我自己写的两个错误**（stool_any 的 trigger 里写了「便血」「黑便」）。

### ⑤ 「吐出来」这种半截话也不给进组

「把痰吐出来」会被误判成呕吐，所以 `vomit_any` 的 trigger 最终收紧为：
`['呕','呕吐','干呕','反胃','吐了','吐得']`

## 五、校验工具

### `tools/check-symptom-groups.js`
固化 6 条规矩：组必须有 children、子必须都是 symptom（不能嵌套组）、不能重复、
**组不得出现在任何 needs 路径里**、trigger 不违禁、+ 9 条行为抽检。

### 行为抽检（全部通过）

| 输入 | 期望 | 结果 |
|---|---|---|
| 干呕吐涎沫 | 呕吐族 + 干呕吐涎沫 成立；恶心**不**成立 | ✓ |
| 恶心想吐但没吐 | 只有恶心；呕吐族**不**成立 | ✓ |
| 咳嗽咳出血来 | 咯血 + 出血族成立；呕吐族**不**成立 | ✓ |
| 把痰吐出来 | 呕吐族**不**成立 | ✓ |
| 不吐血 | 吐血 = no；呕吐族**不得**被判 no | ✓ |
| 没有出冷汗 | 出冷汗 = no；出汗族**不得**被判 no | ✓ |
| 大便带血 | 大便带血 + 出血族 + 大便族 成立 | ✓ |
