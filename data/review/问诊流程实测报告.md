# 问诊流程实测报告：耗时与准确率

**测试要求**（用户）：模拟问诊过程，网上找几个医案试试，一个问题算 2 秒，测试 30 个，看大概需要多久、准确率如何。

**结论先说**：
- **耗时**：30 问 = **60 秒**
- **准确率**：**召回 96.7%（目标方不被误排除），但无法收敛到唯一答案（0%）**
- **根本原因**：条文路径太松——536 条路径里 **69% 只有 ≤2 个条件**，其中 **51 条只有 1 个症状**

---

## 一、测试数据来源

从维基文库抓取曹颖甫《经方实验录》全文（[zh.wikisource](https://zh.wikisource.org/zh-hans/%E7%B6%93%E6%96%B9%E5%AF%A6%E9%A9%97%E9%8C%84)），
用 `tools/extract-jingfang-cases.js` 切成 **60 个真实医案**（跨越 25 种方剂，桂枝汤 6 案、大承气汤 5 案、麻黄汤 4 案…）。

产物：`data/texts/经方实验录-医案.json`

其中 **51 个**能测（目标方剂在库中）；**9 个**测不了，因为方剂本身不在库里：
葛根黄连黄芩汤、桂枝二麻黄一汤、桂枝麻黄各半汤、麻黄附子甘草汤、苓甘五味加姜辛半夏杏仁汤、猪胆汁导（**已核实：不是命名差异，库里确实没有这些方**）。

---

## 二、测法一：真实医案（暴露了词表问题，测不出策略）

`tools/bench-ask.js` — 把医案「诊治记录」喂给探针引擎算出病人真实症状，
然后用医案第一句当开场主诉进入问诊，之后按三态如实回答（明说有→是、明说没→否、**没提到→不知道**）。

### 结果（51 案，30 问上限）

| 指标 | 数值 |
|---|---|
| 平均问题数 | **30.0 问**（顶到上限） |
| 平均耗时 | **60 秒** |
| 其中答「不知道」 | **27.7 问 / 30 问 = 92%** |
| 目标方仍在候选 | 50/51 = **98.0%** |
| 收敛为唯一且正确 | **0/51 = 0%** |
| 平均剩余候选方 | **245.9 个** |

### 这条测法说明什么

**92% 的问题只能答「不知道」**，因为医案是古文写作：
「啬啬恶寒，翕翕发热」「重棉叠衾，尚觉凛然形寒」——这些措辞跟我们白话触发词对不上。

所以真实医案只能证明一件事：**我们不是在误杀正确答案（98% 召回）**，
但没法用它衡量问诊策略，因为病人在仿真里几乎回答不了任何问题。

---

## 三、测法二：教科书病人（能真正衡量策略）

`tools/bench-synthetic.js` — 拿每个方剂**自己 needs 里的某条路径**当教科书病例：
- 路径里 `x.yes` 的 → 病人真的有（含把证候条件**递归展开到叶子症状**）
- 路径里 `x.no` 的 → 病人明确没有
- 其他症状 → 病人都没有

### 结果 A：30 问上限（30 个方剂）

| 指标 | 数值 |
|---|---|
| 平均问题数 | **30.0 问** |
| 平均耗时 | **60 秒（1 分钟）** |
| 其中粗筛问题 | 4.0 问 |
| 目标方仍在候选 | 29/30 = **96.7%** |
| 收敛为唯一且正确 | **0/30 = 0%** |
| 平均剩余候选方 | **69.2 个** |

### 结果 B：放开到 400 问（15 个方剂，看极限）

| 指标 | 数值 |
|---|---|
| 平均问题数 | **82.5 问** |
| 平均耗时 | **164.9 秒（2.7 分钟）** |
| 目标方仍在候选 | 14/15 = **93.3%** |
| 已收敛（无问题可问） | 15/15 = 100% |
| **收敛为唯一正确答案** | **0/15 = 0%** ← 关键 |
| 平均剩余候选方 | **11.3 个** |

### 这条测法说明什么

即使病人完美符合某个方剂的条文，**把能问的问题全问光（82 问、2.7 分钟），
也仍然剩 11 个候选方，一个都没法收敛到唯一答案**。

---

## 四、根因诊断：路径太松

| 统计项 | 数值 |
|---|---|
| 方剂数 | 250 |
| needs 路径总数 | **536** |
| 只有 1 个条件的路径 | **82 条（15.3%）** |
| 只有 2 个条件的路径 | **288 条（53.7%）** |
| **≤2 个条件的路径合计** | **370 条 = 69.0%** |

### 82 条单条件路径分两类

| 类型 | 条数 | 评价 |
|---|---|---|
| 条件是**证候/派生节点**（如 `baihe_bing.yes`、`mei_he_qi.yes`） | 31 | ✅ 可接受——证候本身已经承载了多个症状 |
| 条件是**单个症状**（如 `tili_cha.yes` 体力很差、`pregnancy.yes` 怀孕） | **51** | ❌ **过松，谁有这一个症状就命中** |

这 51 条单症状路径涉及 **43 个方剂**（占 250 个的 17%）。

**最刺眼的例子**：

| 方剂 | 单症状路径 |
|---|---|
| 小柴胡汤 | 有 **4 条**：往来寒热 / 胸胁苦满 / 默默不欲饮食 / 心烦喜呕 —— **沾一个就成立** |
| 补肾组合 | 有 **4 条**：体力很差 / 足跟痛 / 双腿无力 / 小便数 |
| 乌梅丸 | 久利 / 虫积 |
| 桂枝加桂汤 | 奔豚 / 气上冲 |

这直接解释了为什么收敛不了：**只要病人身上碰巧有一个「单症状方」要求的症状，那个方就永远挂在候选里排不掉**，
而这类方剂有 43 个，随便一个病人都能沾上好几个。

---

## 五、诚实的结论

### 能做到的
- ✅ **召回好**：93~98% 的情况下，正确的方剂不会被误排除
- ✅ **可解释**：每个候选方都能列出「凭什么」逐条条件 + 每个节点出自哪本书哪一条
- ✅ **耗时可控**：30 问 60 秒、82 问 2.7 分钟，都在患者能忍的范围内
- ✅ **粗筛有效**：4 个部位/大类问题能把 250 个方压到 160 左右

### 做不到的
- ❌ **无法收敛到唯一答案**：30 问剩 69 个候选、82 问剩 11 个，到不了 1 个
- ❌ **古文医案基本答不上来**：92% 的问题只能答「不知道」

### 这不是问诊策略的问题，是**条文质量问题**

---

## 六、建议的下一步（按性价比排序）

### 1. 收紧那 51 条单症状路径（最优先，收益最大）

把「单症状即可成立」改成「至少 2 个条件，且最好含阴性鉴别」。
例如小柴胡汤：

```js
// 现在（4 条单症状路径，沾一个就成立）
needs: [['alternating_cold_heat.yes'], ['hypochondriac_fullness.yes'],
        ['low_appetite.yes'], ['vex_like_vomit.yes']]

// 建议（守住「往来寒热」这个核心 + 阴性鉴别）
needs: [['alternating_cold_heat.yes', 'hypochondriac_fullness.yes'],
        ['alternating_cold_heat.yes', 'bitter_taste.yes', 'thirsty.no'],
        ['vex_like_vomit.yes', 'hypochondriac_fullness.yes', 'low_appetite.yes']]
```

预计这一步能把 30 问剩余候选从 69 降到 10~20 个。

### 2. 给高频方补阴性鉴别条件

这是这套系统最值钱的部分（用户早就强调过「必须尽量包含阴性症状」），
但很多方剂至今没有。有阴性鉴别的方剂之间才不会互相混淆。

### 3. 扩触发词覆盖

医案里的古文说法（「啬啬恶寒」「翕翕发热」「重棉叠衾尚觉形寒」）
应该映射到 `cold_aversion`。这一步能让真实医案测试变得有意义。

### 4. 或者：改变产品预期

如果接受「**给 3~5 个候选方 + 每个的逐条依据**」而不是「给唯一答案」，
那么现在这套在 82 问时剩 11 个的水平，再收紧一轮路径就基本可用了。
从临床现实看，医生本来也需要鉴别诊断的候选列表，不一定非要唯一答案。

## 七、可复现的命令

```powershell
# 1. 抓取并切分真实医案（60 个）
node tools\extract-jingfang-cases.js

# 2. 真实医案测试（三态诚实回答）
node tools\bench-ask.js --limit 30

# 3. 教科书病人测试（衡量策略与路径质量）
node tools\bench-synthetic.js --limit 30
node tools\bench-synthetic.js --limit 15 --maxq 400   # 看问到底能到多少

# 4. 模拟器（手动看单次问诊过程）
node tools\sim-ask.js "恶心，干呕吐涎沫，胸胁胀满" --smart
```

明细：`data/bench-ask-result.json`、`data/bench-synthetic-result.json`
