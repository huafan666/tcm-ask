### 最重要的收获：把否定条件找回来

原文里的「**不呕 / 不渴 / 无大热 / 不汗出 / 不恶寒 / 不下利 / 不用水 / 头不痛项不强**」
是方证鉴别最锋利的刀，但历史落库时几乎都被当成「伴随症」丢掉了。这次成体系地补：

- 61 条 干姜附子汤：「不呕，不渴，无表证，身无大热」四个否定条件原来一个都没落

- 166 条 瓜蒂散：「头不痛，项不强」是划界限用的，原来写的是猜的「不恶寒」
- 207 条 调胃承气汤：「不吐不下」
- 386 条 五苓散 / 理中丸：分水岭就是「渴与不渴」，原来两边都进不去

## 逐条审核怎么做的

工作台：`tools/audit-shanghanlun.js`

```
node tools/audit-shanghanlun.js --ch 6         # 看某一篇
node tools/audit-shanghanlun.js --seq 31-60    # 看某一段
node tools/audit-shanghanlun.js --gaps         # 只列有缺口的条
node tools/audit-shanghanlun.js --missing      # 列「库里没有的方名」汇总
```

它把「条文原文 / 点到的方 / 现有 needs / 条文否定词 / 症状命中」摆在一起。

方名匹配做了四层容错：繁简转换 → 别名 → 编辑距离 ≤1（吃掉原文错字「桂校附子汤」「自虎汤」）
→ 前后缀包含（原文常把「桂枝去芍药加蜀漆牡蛎龙骨救逆汤」缩成一截）。
**后缀匹配要求短边至少 5 个字**——否则「葛根黄芩黄连汤」会被匹配到「黄连汤」，
把真缺口藏起来（这个坑踩过一次）。

## 已知的遗留

1. **厥热胜复不建模**
   厥阴篇大量「厥几日、热几日」「先厥后热 / 先热后厥」的动态描述（331/336/341/342 等），
   现在的三态模型表达不了"先后"和"多少"。硬塞会造出错误语义
   （把「先厥后热」写成「发热+手足厥冷」就和热厥完全分不出来）。
   这批条文大多不给方，是判断预后传变的，不影响方证命中。
   要处理需要给引擎加「病程相位」维度，属架构改动。

2. **脉象全部不参与**
   `dependsOnPulse` 直接把靠脉判的方剂排除。7 个脉象节点是早期遗留，没有任何 needs 引用。
   伤寒论一半的鉴别力在脉上（尤其是三承气的分立、「脉滑而厥」），目前完全用不上。

3. **2 个方名对不上，都是合理的**
   - 禹余粮丸（88 条）：原文自注「方佚」，方子失传
   - 「及湯」：「然不及湯」被误抽出来的假名

4. **`patchPluginSource` 改写 needs 会连带删掉数组内的行注释**
   每批改完必须 `git diff` 一遍手工补回。三批里共发生过 8 次。
