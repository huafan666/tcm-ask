### 2.7 痉病：三条三元组按病机分组（不是按体征拼凑）

| # | 条件组（AND） | 病机 |

| ① | 颈项强急 + 背反张 + 口噤 | 外邪伤筋、筋脉拘急，及于项背而内及于口 |
| ② | 颈项强急 + 背反张 + 独头动摇 | 津血亏虚、虚风内动 |

## 两条硬约束（踩坑后写进 skill）

1. **多路径节点的各路径之间，不能出现同一节点的 `yes`/`no` 互斥。**
   引擎语义是「任一路径被某条件明确否定 → 整节点判 `no`」（`engine.js` 的 `anyPathBlocked`）。
   第一版把「无汗」放①、「汗出」放②，病人一说"没汗"就把整个痉病判 `no`——哪怕①的条件全满足。
   → 互斥的分流条件（有汗/无汗）应放进**另一个更具体的节点**（刚痉/柔痉），而不是同一节点的不同路径。
2. **trigger 一律关键词数组，说 3~5 个典型说法即可，不穷举、不写函数式/正则触发。**
   漏掉的措辞靠 `ask` 反问补（问句已在每个节点里）。实战例子：病人说"胸口发满""脚抽筋"，
   原来的 `胸满`/`四肢微急` 接不住 → 补同义词，而不是改触发机制。

## 2026-11 修正：柔痉与栝蒌桂枝汤只用临床症状

用户指出两个建模错误，已改：

1. **栝蒌桂枝汤漏了「太阳病」这一层**：原来 `['sweat.yes','neck_stiff_pain.yes','cold_aversion.no']`，
   一个里虚自汗 + 脖子发硬的人就能命中，跟太阳表证无关。
2. **「不恶寒」与库里太阳病定义冲突**：`taiyang_disease` 的内建条件是 `['neck_stiff_pain.yes','cold_aversion.yes']`
   （第 1 条「头项强痛而恶寒」），柔痉若同时要求「不恶寒」，两条互斥、永远判不出来。

改法（用户定的口径：**柔痉单独用症状，不挂太阳证**）：

| 节点 | 现在的 needs | 说明 |
|---|---|---|
| `rou_jing` 柔痉 | `['fever.yes','sweat.yes','neck_stiff_pain.yes']` | 发热 + 汗出 + 身体强几几；「不恶寒」不再作硬条件 |
| `gualou_guizhi_tang` 栝蒌桂枝汤 | `['rou_jing.yes','neck_stiff_pain.yes']` | 柔痉 + 身体强几几（方条多这一层） |

「不恶寒」写进 `contraindications` 作**与刚痉的鉴别说明**：原文作「不恶寒」，临床汗出者多以恶风为主。

回归验证：
- 发烧 + 身上有汗 + 脖子发硬 → 柔痉 ✓ + 栝蒌桂枝汤 ✓（刚痉 ✗、葛根汤 ✗）
- 发烧 + 没有汗 + 怕冷 → 刚痉 ✓（柔痉 ✗、栝蒌 ✗）
- 只有「身上有汗」→ 什么都不成立 ✓（旧版会误判成柔痉）
- 「容易出汗，脖子发硬」（无发热）→ 不成立 ✓
- 痉病三条路径、葛根汤、大承气汤均未受影响

**遗留待定**：`gang_jing` 刚痉现在是 `['fever.yes','no_sweat.yes','cold_aversion.yes']`（照 2.1 原文），
同样没有「筋急」这一层，普通风寒表实证（发热无汗恶寒）会被判成刚痉。
